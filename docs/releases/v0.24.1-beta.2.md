# Flud Companion 0.24.1 Beta 2

Bug-fix beta focused on iPhone PWA pairing persistence and slow Android TV / NVIDIA Shield Flud starts.

## Fixed

- Remote pairing now survives Add to Home Screen on iPhone/iPad by transferring the QR pairing through a short-lived Secure cookie and then storing it inside the installed PWA.
- Auto-start no longer uses its D-pad fallback while Flud is still on the main screen, preventing accidental entry into Select a .torrent file to add.
- The Accessibility helper now recognizes the real Add torrent screen and can confirm the top-right add action even when Flud exposes it as an unlabeled image button.
- A slow/frozen Flud cold start gets a longer guarded window and, if necessary, one controlled magnet re-handoff after Flud has had time to settle.
- If the .torrent file picker is detected, Companion backs out and performs at most one controlled recovery re-handoff.
- The Android Bridge header now reads the real build version instead of showing a hard-coded 0.24.0 label.
- The Remote PWA service-worker cache was advanced for 0.24.1 so installed clients can replace cached 0.24.0 assets cleanly.

## Real-device validation

Confirmed on real NVIDIA Shield / Android TV hardware and iPhone:

1. A fresh Remote QR pairing survives Safari Add to Home Screen and the installed PWA opens already paired.
2. A slow/frozen Flud cold start that takes roughly 7-8 seconds can receive a magnet with Auto-start enabled without falling into the .torrent file picker, and the torrent is added successfully.

## Security and privacy

- The pairing bootstrap cookie is Secure, SameSite=Strict, short-lived, and deleted after it restores pairing in a fresh installed PWA.
- No project-owned account or shared relay is introduced.
- Pairing tokens, QR codes and signing material must remain private.

Flud Companion remains an independent, unofficial alexlab.media project and is not affiliated with Delphi Softwares.
